# Keep table playback, measurement and placement in the frame pipeline

Table row identity follows its stable key through changes in sort order, revealed slots and recorded country tags. Callers can supply a dated tie key separately from that identity. A row revision includes all content and data that its custom cells consume, including failure states. Content-derived column choices can encode a stable persisted sort value. An unsorted table preserves the caller's order, including orders supplied by the recording.

During playback, live cells read one held frame result for text, bars and sort values. A row can draw its tone and bar from a second live value. A missing value leaves no live tone or bar. A changed head value asks React to commit a new row order only when the order changes. Recreating a column without changing its sort accessor retains the current order. A tooltip for a hidden painted column uses the same live value as the cell. The table owns the native, non-passive wheel handler for a scrollable tooltip so the page scroll waits while the tooltip consumes that wheel input.

An unranked table can mount upcoming rows around the viewport. Until their reveal hour they are inert and occupy zero height. Geometry depends on the number of revealed rows, so time advancing within an unchanged reveal cut leaves placement alone. The layout pass marks upcoming rows before entry logic runs. Later frames update their height, placement and reveal state directly. Entry starts once when a row becomes visible, and a departing row can stay mounted long enough to finish a glide even when its destination is outside the viewport. The keyboard skips future rows and can retain a leaving row's focus during its fade. Ranked tables display the complete ranked population and omit this reveal mode.

An order change compares against the last committed ranks. A marker's hold begins at the actual commit even if rendering took longer than expected. Expiry hides the marker in the DOM, avoiding a React commit for each expired marker during playback. Commits update mounted row indices and the rank text directly when rank markers are disabled. The mounted-row callback compares both callback and row identities to avoid a feedback loop when the widget rebuilds its columns in response.

The table reuses text measurements for the same typography, column configuration and sample. During playback a placement can keep wider fitted widths between samples until it refits on pause or another [layout reset](0503-table-playback-widths.md). Rank, identity and sorted columns affect the available tracks, and the identity and sorted columns are protected from hiding. A layout pass hides or restores one priority column at a time against the actual table width. Wrapped heights are observed only for mounted rows. Last measured heights keep positions from collapsing across a width change, with a baseline for new rows. Observations land in the frame's data phase and repeated readings avoid a new commit. Stale measurements are pruned in batches so each departing row does not cause a separate commit.
